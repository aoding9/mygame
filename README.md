# MyGame

本地运行的 Steam 游戏库管理工具，在浏览器中浏览与管理你的 Steam 游戏。支持筛选、收藏、隐藏、随机抽游戏、启动/安装，以及封面与元数据自定义。

## 功能

### 游戏库与缓存

- **Steam 账号**：通过 Token 绑定单个 Steam 账号
- **本地 SQLite 缓存**：游戏库快照、元数据、封面覆盖写入 `data/mygame.db`；**仅手动刷新**时拉取远程数据
- **Token 过期仍可浏览**：缓存库可离线查看；需要更新时再配置 Token
- **家庭共享库**：可选合并家庭成员游戏
- **本地安装库**：读取本机 Steam 安装目录，标记「已安装」并支持筛选

### 浏览与筛选

- **顶栏搜索**：中英文名称、简称与别名（如 `cs2`、`老头环`）
- **筛选抽屉**：类型、标签、时长、所有者、Steam 收藏夹、排序等
- **收藏 / 隐藏**：本地独立保存；支持「仅收藏」「仅隐藏」筛选
- **自适应网格**：固定 4 行展示，列数随窗口宽度变化；底部分页
- **随机抽游戏**：在当前筛选结果中随机挑选，弹窗复用完整卡片交互

### Steam 客户端集成

- **导入隐藏**：从 Steam 客户端配置导入隐藏列表
- **导入收藏夹**：从 Steam 客户端导入收藏夹，用于筛选
- **启动 / 安装**：悬停卡片可启动已安装游戏，或通过 Steam 打开未安装游戏的商店/下载页

### 游戏资料

- **元数据补全**：从 Steam 商店拉取中文名、类型、标签、操作方式（键鼠 / 手柄）
- **锁区回退**：国区无法获取时，自动尝试香港、美区等商店参数（**只读查询，不改账号地区**）
- **无效名过滤**：错误页标题（如「站点错误」）不会写入缓存
- **资料编辑**：自定义显示名、中英文名、类型标签、别名；搜索/上传/本地化封面
- **锁定自定义**：编辑保存后可防止刷新覆盖

### 刷新选项

点击左上角 **刷新数据**，可按需勾选：

| 选项 | 说明 |
|------|------|
| 游戏库列表 | 重新拉取拥有的游戏 |
| 获取分类标签 | 补全商店元数据（中文名、类型、标签、操作方式） |
| 刷新封面 | 重新获取封面 URL |
| 封面本地化 | 将封面下载到 `data/covers/` |

各子项支持「全部刷新」及覆盖本地封面等细项。

### 其他

- **运行日志**：按天写入 `data/logs/`，默认保留 14 天
- **封面清理**：无引用封面定期删除
- **HTTP 代理**：设置中配置，用于无法直连 Steam 时

## 环境要求

- [Node.js](https://nodejs.org/) **22.13.0 或更高版本**（推荐最新 LTS）
  - 项目使用 Node.js 内置模块 `node:sqlite` 作为数据库
  - 启动前会自动执行 `scripts/check-node.js` 校验版本；版本不符时会提示升级
- Windows 推荐双击 `mygame.bat` 启动（依赖 PowerShell 脚本）；其他系统可用 npm 命令

**确认 Node 版本：**

```bash
node -v          # 应显示 v22.13.0 或更高
where node       # Windows：确认 PATH 指向新版本
which node       # macOS / Linux
```

若已安装新版本但仍报错，通常是 PATH 中旧版 Node 优先，请调整环境变量或卸载旧版本。

## 快速开始

### 1. 克隆并安装依赖

```bash
git clone <你的仓库地址>
cd mygame
npm install
```

### 2. 启动

**Windows：** 双击 `mygame.bat`，会在新窗口中自动安装依赖、释放监听端口并打开浏览器。

**命令行：**

```bash
npm start
# 开发模式（监听 src/server.js 变更，无 Ctrl+R 热键包装）
npm run dev
```

`npm start` 通过 `scripts/run-server.js` 启动，终端中：

- **Ctrl+R** — 重启服务
- **Ctrl+C** — 退出

浏览器访问：<http://localhost:3000>（默认端口，见下方「修改端口」）

首次使用点击右上角 **+** 连接 Steam 账号；**设置**（⚙）与 **Token 状态**（🔑，绿/红）也在右上角。

### 修改端口

默认监听 **3000**。若端口被占用，任选一种方式即可：

**方式一：`.env`（推荐）**

复制 `.env.example` 为 `.env`，修改端口后重启：

```bash
cp .env.example .env   # Windows: copy .env.example .env
```

```env
PORT=3001
```

**方式二：`port.txt`**

在项目根目录创建 `port.txt`，写入一行端口号：

```text
3001
```

**方式三：命令行环境变量**

```powershell
# PowerShell（仅当前窗口）
$env:PORT = 3001
npm start
```

```bash
# macOS / Linux
PORT=3001 npm start
```

优先级：命令行 `PORT` > `.env` > `port.txt` > 默认 3000。

## Steam 连接说明

1. 点击右上角用户头像（首次为 **+**）→ **连接 Steam**
2. 在已登录 Steam 的 Edge 中点击 **获取 Token**，打开 Token 页后 **全选复制整页 JSON** 粘贴到对话框，会自动提取 `webapi_token` 并预览头像、昵称与 Steam ID（**无需手动填写 ID**）
3. [Web API Key](https://steamcommunity.com/dev/apikey) 可选；填写后可使用 Steam Web API 拉取资料，不填则尝试社区公开页
4. 保存后完成账号连接；再次粘贴相同 Token 会提示重复
5. 连接后默认加载本地缓存；点击 **🔑** 可更新 Token（绿点=有效，红点=未配置或过期）
6. 点击 **刷新数据** 可选择要更新的内容；Token 过期后会提示「显示缓存」

> **注意**：账号凭证与 Token 仅存储在本机 `data/` 目录，请勿将该目录提交到 Git 或分享给他人。

## 游戏资料与锁区

部分游戏在国区商店无法访问，补全元数据时可能拿不到中文名。

**程序行为：**

1. 依次用不同商店区域参数（`cn` → `hk` → `us`）**只读查询**公开商店 API
2. 不会修改 Steam 账号的商店国家或钱包地区
3. 过滤「站点错误」等无效标题；失败时保留游戏库中的英文名

**手动修正（单个游戏）：**

1. 悬停卡片 → **编辑**
2. 填写 **显示名称** 或 **中文名** → 保存
3. 或在编辑弹窗点击 **从平台刷新资料** 重试（建议已在设置中配置代理时重试）

## 数据目录

首次运行后会在项目根目录生成 `data/`（已在 `.gitignore` 中忽略）：

| 路径 | 说明 |
|------|------|
| `data/mygame.db` | SQLite（游戏库快照、元数据、覆盖记录、迁移） |
| `data/users.json` | Steam 账号配置与 API Key |
| `data/steam-token-<用户ID>.json` | Steam Token |
| `data/favorites-<用户ID>.json` | 收藏列表 |
| `data/hidden-<用户ID>.json` | 隐藏列表 |
| `data/collections-<用户ID>.json` | 导入的 Steam 收藏夹 |
| `data/app-settings.json` | 应用设置（Steam 路径、代理、日志、封面清理等） |
| `data/meta/` | 元数据 JSON 缓存（与数据库互补） |
| `data/covers/` | 本地化封面图片 |
| `data/logs/` | 运行日志（按天滚动，默认保留 14 天） |

## 项目结构

```
mygame/
├── public/                 # 前端页面与静态资源
├── src/
│   ├── server.js           # Express 服务入口
│   ├── platforms/          # Steam 本地库、Epic/Ubisoft 等占位

│   ├── db/                 # SQLite、迁移脚本、游戏/元数据存储
│   ├── stores/             # 账号、收藏、收藏夹、设置等 JSON 存储
│   └── services/           # 封面、筛选、元数据、日志、Token 校验、清理
├── scripts/
│   ├── check-node.js       # 启动前校验 Node 版本与 node:sqlite
│   ├── resolve-port.js     # 解析 PORT（.env / 环境变量 / port.txt）
│   ├── run-server.js       # 启动包装（Ctrl+R 重启）
│   ├── start-mygame.ps1    # Windows 启动脚本
│   └── kill-port.ps1       # 释放占用端口
├── .env.example            # 环境变量示例（复制为 .env 后修改）
├── mygame.bat              # Windows 一键启动
└── package.json
```

## 技术栈

- **后端**：Node.js 22.13+、Express、`node:sqlite`（内置 SQLite，含迁移）
- **前端**：原生 HTML / CSS / JavaScript
- **网络**：undici（支持 HTTP 代理）

## 常见问题

### 启动报错 `No such built-in module: node:sqlite`

当前 Node.js 版本过低。请升级到 **22.13.0+**，并确认 `node -v` 输出正确版本。`mygame.bat` / `npm start` 会在启动前自动检测并给出提示。

### 端口被占用（EADDRINUSE）

在项目根目录创建 `.env` 并设置 `PORT=3001`，或创建 `port.txt` 写入端口号，保存后重新启动。
